# Белые списки и контрольный тест YouTube

Общий серверный выход для действующих ключей и резервный вход Yota описаны в
[серверной схеме YouTube и Yota](server-youtube-and-yota.md).

Источники проверены 6 октября 2026 года. Аудит адреса и отдельный клиентский
профиль позволяют проверить доступность входа и влияние прямого выхода YouTube.
Это подготовленные проверки, а не подтверждённый обход ограничений или
отсутствие рекламы.

## Белый список оператора: что уже проверено

Источник наблюдений — [hxehex/russia-mobile-internet-whitelist](https://github.com/hxehex/russia-mobile-internet-whitelist).
Версия: `fad3653ebd4b212643774a4d10af3eb33838e4ff`, файл `cidrwhitelist.txt`.
В зафиксированном файле 30 228 уникальных подсетей; адрес текущего VPS
`5.187.0.217` в них не найден. SHA-256 файла:
`149d27a8e3502b95b9a378817854c87af6417c2a9bbf0b17eb8f7affef1f3868`.

Это не полный список всех операторов, не список SIM пользователя и не проверка
доступности. Отсутствие IP не доказывает блокировку, наличие — работу туннеля.
Наблюдения зависят от оператора, региона и режима ограничений. В README источника
отдельно описано различие SNI-фильтрации и проверки IP вместе с SNI.

Добавлен аудит адреса по этому источнику:

```bash
python3 tools/whitelist_audit.py --server-ip 5.187.0.217
```

Скрипт скачивает зафиксированный текстовый файл по HTTPS, проверяет IP/CIDR,
размер и непустой результат. Он не подключается к VPS, не сканирует адреса,
не меняет маршрутизацию, ключи, DNS или службы. Непригодный список/ошибка загрузки
дают `monitor_inconclusive`, а не вывод о блокировке. JSON на stdout содержит
время, версию и хеш источника, совпавшие подсети и явные
`operator_reachability: not_tested`, `vless_session: not_tested`.

Проверить заранее скачанный список без интернета:

```bash
python3 tools/whitelist_audit.py --server-ip 5.187.0.217 --list cidrwhitelist.txt
```

После проверки нового коммита можно указать полный SHA через `--ref`. Неизвестные
изменения `main` не подхватываются автоматически.

### Что проверять во время ограничений

1. Записать время, город/район и оператора SIM; отключить Wi-Fi и другие VPN.
2. В браузере проверить один обычно разрешённый ресурс (например, Яндекс) и один
   внешний HTTPS-ресурс. Записать ошибки/тайм-ауты, не объявляя причину по двум
   сайтам. Полное отсутствие связи отличается от частичных ограничений.
3. Включить действующую подписку Happ и загрузить реальную страницу через туннель.
   IP геолокации и TCP-пинг сами по себе не проверяют VLESS.
4. Если основной вход недоступен, проверить отдельный вход. Возможная схема:
   устройство → собственный узел с доступным IP → нынешний зарубежный выход.
   Российский VPS имеет смысл после проверки конкретного IP на нужной SIM,
   а не по названию хостинга или совпадению с подсетью.

`geoip:ru-whitelist` в клиентском direct-списке не создаёт вход в туннель.
Широкий direct-список не включён. На действующем WS/TLS нельзя просто заменить
SNI на чужой домен: сертификатная проверка остаётся обязательной. REALITY требует
согласованной серверной и клиентской конфигурации. Проверка сертификата не
отключается; фиктивного резервного узла нет.

## YouTube: проверка без покупки второго сервера

[BlancVPN в FAQ](https://blancvpn.com/ru/help/how-to-set-up-vpn-on-smart-tv)
связывает YouTube без рекламы со своей российской локацией.
[Google](https://support.google.com/adspolicy/answer/6368711?hl=en) продолжает
указывать приостановку Google Ads для пользователей в России. Это поддерживает
гипотезу о географии выхода, но не раскрывает маршрутизацию BlancVPN на всех
локациях и не гарантирует отсутствие рекламы у нашего аккаунта.

[AdGuard](https://adguard-dns.io/kb/adguard-home/faq/) объясняет ограничения
DNS-фильтрации рекламы YouTube, использующей общие домены с видео. Блокировка
`googlevideo.com`, общие рекламные категории и TLS MITM не включаются.

Профиль `youtube-direct-test` имеет имя `SA VPN - YouTube direct test`. Он
сохраняет исключения Эльбы/AnyDesk и proxy для Instagram/Meta/WhatsApp; известные
домены YouTube идут через местного провайдера устройства. Это контрольный опыт,
а не обход замедления YouTube. Провайдер видит соединения к YouTube, YouTube —
местный выходной IP. Вне России профиль использует местный IP, а не специально
российский. При прямой блокировке/замедлении видео может работать хуже или не
работать. Отсутствие рекламы не обещается.

Экспортировать отдельно от подписки:

```bash
python3 tools/export_client_profiles.py --profile youtube-direct-test --format happ-link
```

Ссылка `happ://routing/add/` добавляет отдельный профиль без принудительной
активации. Выбрать его нужно вручную в разделе маршрутизации Happ. Сервер и URL
подписки не меняются. Нет зависимости от большой внешней категории
`geosite:youtube`, которая могла бы вернуть YouTube в proxy.

### Сравнение и возврат

1. При baseline открыть 5–10 одинаковых роликов в приложении YouTube с одним
   аккаунтом. Записать вставки, качество и буферизацию.
2. Импортировать и выбрать `SA VPN - YouTube direct test`, переподключить VPN,
   полностью закрыть/открыть YouTube. Повторить просмотр в той же сети.
3. Проверить Эльбу и Instagram. Один сеанс без рекламы — наблюдение, а не
   доказательство постоянного эффекта.
4. Для возврата выбрать `SA VPN - RU direct` и переподключить VPN. При обновлении
   подписки проверить выбранную маршрутизацию: серверный `onadd` может снова
   выбрать baseline. Подписку/ключи удалять не нужно.

Явное серверное применение через
`apply_happ_routing_3xui.py --profile youtube-direct-test` меняет профиль для всех
подписок и перезапускает 3x-ui. Для первого опыта предпочтителен отдельный
клиентский импорт. Резервная копия/проверки ключей при серверном применении те же.

Если в прямом режиме рекламы меньше, но качество неудовлетворительно, следующий
опыт — собственный/разрешённый российский выход только для YouTube с зарубежным
выходом для остальных сервисов. Тот же узел потенциально можно использовать как
вход при белых списках; оба свойства проверяются независимо. Серверные правила
по входящим тегам должны исключать петлю Россия → Германия → Россия → Германия.
Второй узел этой доработкой не создан и не оплачен.
