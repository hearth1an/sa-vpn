# SA VPN — техническая документация

[Короткая инструкция по установке](../README.md)

## Основной сценарий при смене VPS

Купите новый чистый VPS с Ubuntu 22.04/24.04, войдите как root и выполните команду
из раздела «Установка». Полученные ссылки подписок либо VLESS-ключи скопируйте в Happ.
Новая установка создаёт **новые** UUID и токены: переносить прежние ключи не требуется.
Старый сервер для этого не нужен. Ссылки подписок предпочтительнее отдельных ключей:
они позволяют получать будущие изменения настроек.

## Внешний мониторинг

Workflow `VPN availability monitor` проверяет адреса из `monitoring/targets.json`
каждый час (GitHub может задерживать запуск). Он выполняется вне VPS, поэтому
продолжает работать при потере доступа к самому серверу.

Через API Check-Host выбираются до трёх российских узлов разных ASN и до трёх
зарубежных узлов разных стран/ASN. Если минимум два российских узла не подключаются,
а минимум два зарубежных подключаются, это **признак возможной региональной блокировки**.
Если отказывают и российские, и зарубежные проверки — сервер недоступен шире.
Смешанные результаты отмечаются как частичная недоступность; отсутствие результатов
не считается успешной проверкой. Неуспешная проверка повторяется перед подтверждением.

Подтверждённый инцидент создаёт GitHub Issue с префиксом `[SA VPN monitor]`.
При повторении обновляется существующий Issue; при восстановлении он закрывается.
Сбой самого API мониторинга фиксируется отдельно. Доступен ручной запуск workflow.

**Граница проверки:** TCP 443 может открываться, а VPN-сессия — блокироваться после
начала обмена. Это не полноценная VLESS-проверка из домашней/мобильной сети и не
доказательство действий РКН. Для неё нужен отдельный клиент-проверяющий внутри России.
Check-Host получает только публичный IP и порт; ключи и подписки ему не передаются.

При смене VPS замените IP в `monitoring/targets.json` или попросите сопровождающего
сделать это. Установка на новом сервере не может сама менять GitHub без авторизации.
Существующая задача уведомлений ChatGPT может читать инциденты через GitHub.

Собственный VPN на чистом VPS одной командой. Без покупки домена.

**Статус: первая версия.** Проверки конфигураций и реального протокола автоматизированы;
полную установку с выдачей публичного сертификата нужно проверить на отдельном чистом VPS.
Не запускайте установщик на действующем сервере с 3x-ui: он откажется менять его.

## Установка

Требуется чистая Ubuntu 22.04 или 24.04, amd64/arm64, systemd, публичный IPv4
и доступ root. Откройте входящие TCP **80, 443, 2096** в панели провайдера.
SSH оставьте доступным. Порт 80 нужен постоянно для продления сертификата.

После входа по SSH выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/hearth1an/sa-vpn/main/install.sh | bash
```

GitHub-репозиторий должен быть **публичным**, иначе эта команда без авторизации не работает.
Для контроля загрузки и просмотра скрипта перед запуском:

```bash
curl -fSL https://raw.githubusercontent.com/hearth1an/sa-vpn/main/install.sh -o /tmp/sa-vpn-install.sh && bash /tmp/sa-vpn-install.sh
```

Если вы вошли не от root, используйте `sudo bash` вместо `bash`.
В конце установки скрипт спросит, сколько ключей выдать: **от 1 до 5**.
Профили называются **1, 2, 3, 4, 5** соответственно, каждый со своим UUID и токеном.
Скрипт выдаст выбранное количество подписок, ссылки VLESS и QR-коды.
Ввод читается из SSH-терминала (`/dev/tty`), поэтому работает и через `curl | bash`.
В Happ выберите добавление подписки по ссылке. QR тоже содержит URL подписки.

Если автоматическое определение адреса неверно (например, дополнительный NAT):

```bash
sudo env SA_VPN_IP=ВАШ_ПУБЛИЧНЫЙ_IPV4 bash /tmp/sa-vpn-install.sh
```

Опционально задайте `SA_VPN_EMAIL=email@example.com` для регистрации ACME с почтой.
Иначе ACME регистрируется без почты. Установка принимает условия Let's Encrypt.

## Что устанавливается

- Xray **v26.6.27** (версия исходного рабочего сервера; закреплена, архив проверяется SHA-256).
- VLESS + WebSocket + TLS на 443. TLS завершается в nginx, Xray слушает только 127.0.0.1:10000.
- HTTPS-подписки на 2096 с независимыми случайными токенами.
- Certbot **5.4.0** в отдельном Python venv, сертификат Let's Encrypt для IPv4.
- Проверка продления каждые 6 часов и автоматическая перезагрузка сертификата nginx.
- Ежедневная резервная копия пользователей и WebSocket-пути.

Панель 3x-ui в этой сборке не устанавливается. Управление выполняет `sa-vpn`.
Сторонние компоненты сохраняют свои лицензии: [Xray](https://github.com/XTLS/Xray-core),
[nginx](https://nginx.org), [Certbot](https://github.com/certbot/certbot).
Код обвязки SA VPN распространяется по MIT.

IP-сертификат действует около шести дней. Автопродление обязательно:
[официальное описание Let's Encrypt](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).
Смена IP требует нового сертификата и новых URL подписок.

## Управление

```bash
sa-vpn links              # Показать подписки и VLESS-ссылки
sa-vpn add laptop        # Создать отдельного пользователя
sa-vpn revoke laptop     # Отозвать UUID и подписку пользователя
sa-vpn doctor            # Проверить службы, сертификат и подписки
sa-vpn backup            # Создать копию и показать её путь
sa-vpn restore /root/backup.tar.gz
```

Команды выполняются от root / через sudo. Добавление и отзыв перезапускают Xray,
поэтому активные подключения кратковременно прервутся.
Повторный запуск завершённого установщика проверяет сервис и выводит прежние ссылки.
Он не обновляет версии и не генерирует ключи повторно.

## Перенос на другой VPS

1. На старом сервере выполните `sa-vpn backup` и скачайте полученный архив.
2. На новом чистом VPS установите SA VPN обычной командой.
3. Скопируйте архив на новый сервер и выполните `sa-vpn restore /root/backup.tar.gz`.
4. Получите подписки с новым IP и замените ссылки в Happ.

UUID, токены и WebSocket-путь сохранятся. IP берётся от нового VPS;
его сертификат выпускается при установке. Сертификаты, приватные TLS-ключи,
бинарники и системные настройки не переносятся из архива.
Это резервная копия пользователей SA VPN, не импорт базы 3x-ui.

Копии находятся в `/var/backups/sa-vpn`, без автоматического удаления.
Храните отдельную копию вне VPS: локальная копия не спасёт при потере сервера.
Архив содержит секреты; не публикуйте его, `state.json` или ссылки подписок.
Подписки доступны каждому обладателю URL. Журналы доступа nginx отключены.

## Проверка и диагностика

Установщик проверяет TLS → WebSocket → VLESS → исходящий HTTPS через временный
SOCKS-клиент и сравнивает IP выхода с адресом VPS. Это локальный тест на сервере;
доступность из России и влияние фильтрации провайдера проверяются в Happ.
Подписка передаёт Happ профиль маршрутизации `SA VPN - RU direct`: российские домены
и IP, сервисы Контура (включая Эльбу), Ozon/Wildberries и AnyDesk идут напрямую,
а явно перечисленные зарубежные сервисы — через VPN. После изменения профиля в
репозитории достаточно обновить подписку в Happ. Отдельно импортированный профиль
маршрутизации в клиенте может иметь больший приоритет и потребовать отключения.

Для ранее установленного сервера с 3x-ui примените тот же профиль без переустановки
и без замены пользовательских ключей:

```bash
curl -fsSL https://raw.githubusercontent.com/hearth1an/sa-vpn/main/tools/apply_happ_routing_3xui.py | sudo python3
```

Скрипт создаёт резервную копию базы 3x-ui, проверяет неизменность VPN-входов и
автоматически возвращает прежние настройки, если проверка завершится ошибкой.

```bash
sa-vpn doctor
systemctl status sa-vpn-xray nginx sa-vpn-renew.timer
journalctl -u sa-vpn-xray -n 50 --no-pager
journalctl -u sa-vpn-renew -n 50 --no-pager
systemctl start sa-vpn-renew.service
```

Если сертификат не выдан: проверьте публичный IPv4, доступ извне к TCP 80,
firewall провайдера и лимиты Let's Encrypt. При ошибке установка останавливается;
после исправления допускается повторный запуск. Полного отката установленных
пакетов нет. Скрипт не отключает firewall и не меняет SSH; если UFW уже активен,
он добавляет разрешения для трёх нужных портов.

## Разработка

`install.sh` — самодостаточная сборка `install.template.sh` и `manager.py`.
При изменении исходников пересоберите её:

```bash
python3 build.py
python3 build.py --check
bash -n install.sh
python3 -m unittest discover -s tests -v
```

GitHub Actions проверяет обе версии Ubuntu, ShellCheck, управление ключами,
восстановление, настоящий туннель с nginx/Xray и проверяемым тестовым сертификатом.
ACME-выпуск, systemd-установка и внешний firewall требуют отдельного VPS-теста.
Обновления зависимостей выполняются явно с обновлением версии и SHA-256;
автоматического скачивания «latest» для Xray нет.
